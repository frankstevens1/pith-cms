# Quick start

Add the CLI and scaffold a project in two commands:

```sh
pnpm add @pith-cms/cli
pnpm pith init
# pnpm pith init --storage github   # GitHub-backed storage
```

`init` installs the runtime dependencies for your chosen storage adapter
(`@pith-cms/core`, `@pith-cms/next`, `server-only`, and either
`@pith-cms/storage-filesystem` or `@pith-cms/storage-github`) and writes the
configuration files. After it finishes you can start customising.

Start with filesystem storage locally — it needs no extra configuration. Switch
to GitHub later when you are ready to publish.

## What init creates

- **`pith.config.ts`** — a starter config with a `pages` collection using JSON files.
- **`src/lib/pith.ts`** — the Pith instance wired to your config and storage adapter.
- **`app/(cms)/layout.tsx`** — a minimal route group layout that imports the editor stylesheet and theme script.
- **`app/(cms)/_components/`** — reusable theme components (`theme-script.tsx`, `theme-toggle.tsx`).
- **`app/(cms)/pith/[[...pithPath]]/page.tsx`** — the editor page inside the `(cms)` route group.
- **`app/api/pith/[...pithRoute]/route.ts`** — the editor API route.
- **`content/pages/`** — the content directory with a `.gitkeep` placeholder.
- **`.env.example`** — environment variable stubs for auth and preview secrets.

> **Note:** `init` intentionally skips layout changes — it never mutates your existing source files.

## Next steps after init

Set up authentication and preview secrets:

```sh
pnpm pith auth hash-password          # prompts for a password, copies the hash
pnpm pith auth generate-secret        # generates both secrets, copies to clipboard
```

Add them to your environment:

```env
PITH_PASSWORD_HASH=...    # editor login password (Argon2id hash)
PITH_SESSION_SECRET=...   # encrypts editor session cookies
PITH_PREVIEW_SECRET=...   # enables draft previews via query param
PITH_SESSION_SECURE=false # set to true in production with HTTPS
```

> **Note:** For GitHub storage, the generated `.env.example` includes additional variables for owner, repository, branch, and authentication. See [Storage](./storage.md) for token and publishing configuration.

## Layout structure

Pith mounts the editor inside a `(cms)` route group so its layout stays isolated from your public pages. The root layout should remain minimal:

```tsx
// app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>{children}</body>
    </html>
  );
}
```

If your existing root layout has shared UI (navigation, header, footer, sidebars), move that UI into an `(app)` route group layout:

```
app/
  layout.tsx           ← minimal: <html>, <body>, fonts, providers
  (app)/
    layout.tsx         ← your existing shared UI (nav, header, footer)
    page.tsx           ← your existing public pages
    .../
  (cms)/
    layout.tsx         ← generated by pith init (editor.css + theme)
    pith/[[...pithPath]]/page.tsx
  api/
    pith/[...pithRoute]/route.ts  ← editor API (outside route groups)
```

Next.js route groups — directories wrapped in parentheses like `(app)` and `(cms)` — do not affect URL paths. They only affect which layout wraps which routes.

## Customise your collections

Define new collections by editing `pith.config.ts` directly, or using the
interactive CLI — `pnpm pith collection add` — which creates the content
subdirectory with a `.gitkeep` placeholder for you.

To add one manually:

```ts
// pith.config.ts
import { defineCollection, definePith, field } from '@pith-cms/core';

export default definePith({
  contentRoot: 'content',
  collections: {
    pages: defineCollection({
      path: 'pages',
      format: 'json',
      identifierField: 'slug',
      displayField: 'title',
      fields: {
        title: field.text({ required: true }),
        slug: field.slug({ source: 'title', required: true }),
        description: field.text({ multiline: true }),
      },
    }),
  },
});
```

## Add content

Create entries in `content/[collection]/[entry].json`:

```json
// content/pages/home.json
{ "title": "Home", "slug": "home", "description": "A Pith site." }
```

## Read content

There are two content clients. Which one you use depends on whether you have an
incoming request:

| Client                      | Use when                              | Honors previews? |
| --------------------------- | ------------------------------------- | :--------------: |
| `pith.content.forRequest()` | Pages and components during a request |       Yes        |
| `pith.content`              | Build time, scripts, metadata         |        No        |

### During a request

```tsx
// app/page.tsx
import { pith } from '@/lib/pith';

export default async function HomePage() {
  const content = await pith.content.forRequest();
  const page = await content.getEntry('pages', 'home');

  return <h1>{page.value.title}</h1>;
}
```

`forRequest()` is for pages that render content during a request. When a preview
is active, it overlays draft content.

### Outside a request

```tsx
// app/posts/[slug]/page.tsx
import { pith } from '@/lib/pith';

export async function generateStaticParams() {
  return (await pith.content.getEntryIdentifiers('posts')).map((slug) => ({ slug }));
}

export async function generateMetadata({ params }: { params: { slug: string } }) {
  const post = await pith.content.getEntry('posts', params.slug);
  return { title: post.value.title };
}
```

Use `pith.content` for `generateStaticParams`, `generateMetadata`, build scripts,
or any code that runs without an incoming request. It always returns canonical
content — previews are not available here.

Run `pnpm dev`, visit `/`, then sign in at `/pith`.
